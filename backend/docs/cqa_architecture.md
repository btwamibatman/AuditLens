# CQA Backend Architecture & Gemini Integration Guide

## 1. Безопасность API-ключа

- Переменная: `GEMINI_API_KEY` в корневом `.env`.
- `.env` находится в `.gitignore` и **ни при каких условиях не коммитится в Git**.
- В Git коммитится только `.env.example` с пустым значением:

  ```env
  LLM_PROVIDER=gemini
  GEMINI_API_KEY=
  GEMINI_MODEL=gemini-3.6-flash
  GEMINI_THINKING_LEVEL=medium
  LLM_BATCH_CONCURRENCY=4
  LLM_PRICE_INPUT_PER_1M=1.50
  LLM_PRICE_OUTPUT_PER_1M=7.50
  DATASET_API_URL=
  ```

- Если `GEMINI_API_KEY` не задан (или `LLM_PROVIDER=mock`), бэкенд автоматически работает в **mock-режиме** — генерирует валидные оценки-заглушки для отладки UI без вызова внешнего API и без траты токенов.

## 2. Актуальные модели Gemini (серия 3.x)

По официальной документации Google Gemini API (Interactions API):

| Модель | Model ID в SDK | Thinking по умолчанию | Pricing (1M in / out) | Когда использовать |
| --- | --- | --- | --- | --- |
| **Gemini 3.6 Flash** (по умолчанию) | `gemini-3.6-flash` | `medium` | **$1.50 / $7.50** | Основная модель: баланс рассуждений, точных цитат и скорости. |
| **Gemini 3.5 Flash-Lite** | `gemini-3.5-flash-lite` | `minimal` | **$0.30 / $2.50** | Максимальная скорость и минимальная цена при пакетных прогонах. |
| **Gemini 4 Argon** | `gemini-4-argon` | `high` | enterprise | Флагман глубокого рассуждения (если критична точность любой ценой). |

> **Устаревшие версии**: `gemini-1.5-*`, `gemini-2.0-*`, `gemini-2.5-*` в новом Interactions API объявлены legacy/deprecated. Для «3.5» используется `gemini-3.5-flash-lite`, для «3.6» — `gemini-3.6-flash`. Переключение между ними — одна строчка `GEMINI_MODEL=...` в `.env`.

### Расчёт экономики для жюри (на базе gemini-3.6-flash)

- Типовой диалог (вход = транскрипт + промпт ~2 000 токенов):  
  `2 000 / 1 000 000 × $1.50 = $0.003`
- Ответ модели (~500 токенов ответа + ~500 токенов thinking = ~1 000 токенов output):  
  `1 000 / 1 000 000 × $7.50 = $0.0075`
- **Итого за 1 диалог**: **~$0.0105 (≈ 5.2 ₸)**
- **Весь пул из 75 диалогов**: **~$0.79 (≈ 390 ₸)**
- Для более дешёвого варианта `gemini-3.5-flash-lite`: 1 диалог **~$0.003 (≈ 1.5 ₸)**, 75 диалогов **~$0.23 (≈ 115 ₸)**.

## 3. Как модель подстраивается под чек-лист (без хардкода)

Промпт и JSON-схема строятся **динамически** из `ChecklistConfig`:

1. **System Instruction** генерируется из списка `config.active_criteria`:
   - Название, секция, формулировка того, что проверять.
   - Тип ответа: бинарный (0/1) или шкала с описанием каждого уровня.
   - Правило применимости N/A (если `na_allowed=True`).
   - Правило фиксации грубой ошибки (если `is_critical=True`).
   - Язык объяснений и заметки компании (`evaluator_notes`).
2. **JSON Schema** для нативного Structured Output:
   - Поле `criterion_id` валидируется через `enum` ровно с ID текущих активных критериев.
   - Модель аппаратно не может вернуть «лишние» или забытые ID.
3. **Фильтрация по каналу**:
   - Критерии с `channels=["call"]` (например, «интонация и дикция») для чатов автоматически переводятся в `N/A` бэкендом без лишнего расхода токенов.
4. **Математика скоринга**:
   - При N/A вес критерия перераспределяется между применимыми.
   - Итог нормируется к 100 и округляется по правилам чек-листа (`half_up`, `floor`, `ceil`).
   - Грубая ошибка помечается отдельно и по политике `zero_total` обнуляет итоговый балл, сохраняя исходную оценку до ошибки.
5. **Верификация доказательств (Grounding)**:
   - Бэкенд проверяет, что цитата `quote` реально присутствует в реплике `[#index]` транскрипта.
   - Если модель ошиблась индексом, бэкенд ищет совпадение по всему диалогу и корректирует индекс (ставит `verified=True`).

## 4. Сценарий 23-го часа (контрольные 10 транскриптов + замена критерия)

1. Организаторы дают новый `group_id` (например, `CONTROL`) и просят заменить критерий.
2. В интерфейсе (или через `PUT /api/checklists/1`) заменяем критерий. Версия чек-листа автоматически инкрементируется (`v1 → v2`).
3. Запускаем пакетный прогон одной командой:

   ```bash
   python -m app.features.evaluations.batch --group CONTROL --sync
   ```

   Либо через API:

   ```bash
   POST /api/conversations/sync?group_id=CONTROL
   POST /api/evaluations/batch {"dataset_group": "CONTROL"}
   ```

4. Пакетный раннер выполняет запросы параллельно (`LLM_BATCH_CONCURRENCY=4`), логирует прогресс, сохраняет результаты в БД и выгружает `data/exports/CONTROL_<timestamp>.json` и `.csv`.
