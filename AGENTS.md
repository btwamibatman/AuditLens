## 1. Цель и правила работы

Сделать воспроизводимый прототип, который принимает выданные диалоги, оценивает именно оператора по настраиваемому чек-листу, показывает проверяемые доказательства, позволяет оспорить оценку и сохраняет результат в формате организаторов.

- Использовать текущие FastAPI, SQLAlchemy, Pydantic, Vue 3 и TypeScript. Новые библиотеки добавлять только при доказанной необходимости.
- Перед каждым блоком кратко назвать изменение, причину и способ проверки. После — файлы, результаты проверок и оставшиеся ограничения.

- AI-вызовы не включать в обычные тесты. Реальные прогоны выполнять с известным числом запросов и согласованным объёмом; считать все попытки, ошибки и задержки. Не запускать 65 диалогов автоматически вслед за единичной проверкой.

## 3. Требования, которые нельзя потерять

### Вход

Ответ организаторов: `{error, isSuccess, data: {dataset_group_id, total_records, records}}`.

Запись: `{conversation_id, channel, language, transcript, audio_url}`. Реплика: `{timestamp, speaker, text}`. Роли: `client`, `operator`, `bot`, `system`. Каналы: `agent chat`, `voice call`. Языки: RU, KZ, EN.

Сохранять исходные ID, все роли, порядок и timestamps. Чат использует MM:SS, звонок — ISO 8601 с часовым поясом. Транскрипты звонков уже предоставлены: распознавание речи не требуется. Ссылка на аудио нужна для прослушивания/перехода к записи.

### Стартовый чек-лист и результат

| ID | Допустимое значение при сдаче | Вес | N/A |
| --- | --- | ---: | --- |
| contact | true / false | 10 | Нет |
| discovery | true / false / null | 15 | Данных хватало с самого начала |
| identification | true / false / null | 20 | Запрос не требовал идентификации |
| consultation | 0, 5, 10, 15, 20 / null | 20 | Чат закончился до формулировки запроса |
| empathy | true / false | 15 | Нет |
| dialogue | 0, 4, 7, 10 | 15 | Нет |
| closure | true / false / null | 5 | Чат оборвался до возможности завершения |
| critical | true / false | 0 | Нет |

- `closure`: оператор (подвёл итог ИЛИ предложил дальнейшую помощь) И попрощался. Одного прощания или благодарности клиента недостаточно. Итог может относиться к нескольким последним репликам; не требовать искусственной фиксированной фразы.
- `critical`: оскорбление клиента, предложение платной услуги в обход компании, раскрытие конфиденциальной информации. Это отдельный признак, не обнуление балла и не дополнительный вес.
- Шкальный вклад = значение / максимум шкалы × вес. При N/A исключить критерий и пропорционально перераспределить вес. Итог округлить до двух знаков. При отсутствии применимых весов итог не рассчитывается, а не равен нулю.
- Проверять оператора, не засчитывать ему действия бота. Подтверждение идентификации в системном сообщении учитывать как доказательство по правилам ТЗ.
- Оценки «Нет», N/A и ошибка обработки имеют разный смысл, не подменять одно другим.
- По каждому критерию нужны обоснование и доказательства; для пропущенного действия — место/проверенный участок.
- В официальном `evidence_turns` нумерация с 1 по полному исходному массиву, включая клиента, бота и системные события. Внутренние индексы сейчас с 0; преобразовать ровно один раз при экспорте.
- Порог первой реакции в 3 минуты, теги и вложения в оценку не входят.

### Демонстрация

Через UI: изменить критерий → сохранить конфигурацию → выбрать диалог → запустить оценку → открыть доказательство → подать апелляцию → принять решение с причиной → увидеть исходную и финальную оценки с пересчитанным итогом. Для демонстрации не нужен вход в систему. Интерфейс должен быть пригоден для будущей адаптации как HTML-компонент Dynamics 365; реализовывать саму интеграцию сейчас не требуется.

## 7. Существующие API для интеграции

Все пути ниже начинаются с `/api`. Источник точных типов — текущие Pydantic-схемы и `/api/openapi.json`, а не предположения frontend.

| Действие | Метод и путь | Вход / замечание |
| --- | --- | --- |
| Диалоги | GET `/conversations` | query: dataset_group, language; ответ — массив, не Page |
| Транскрипт | GET `/conversations/{id}` | transcript + audio_url и метаданные |
| Получить набор | POST `/conversations/sync?group_id=DEV` | JSON-тело не требуется; нужен DATASET_API_URL на сервере |
| Ручной импорт | POST `/conversations/import` | `{dataset_group, records}`; обёртку invoke.json адаптировать на клиенте |
| Чек-листы | GET `/checklists` | массив конфигураций |
| Активный | GET `/checklists/active` | выбранная конфигурация |
| Шаблон ТЗ | GET `/checklists/default-config` | исправленная конфигурация из кода |
| Создать | POST `/checklists` | `{name, description, config}`; новый не активен автоматически |
| Изменить | PUT `/checklists/{id}` | поля name/description/config; config увеличивает version |
| Активировать | POST `/checklists/{id}/activate` | одна активная конфигурация |
| Оценить | POST `/evaluations` | `{conversation_id, checklist_id}`; синхронный ответ EvaluationRead (201); при занятости 429 / evaluation_busy |
| Оценки | GET `/evaluations` | query: conversation_id, checklist_id |
| Карточка | GET `/evaluations/{id}` | ai_result, final_result, метаданные |
| Промпт | GET `/evaluations/prompt-preview` | query: conversation_id, checklist_id; не вызывает модель |
| Batch | POST `/evaluations/batch` | conversation_ids или dataset_group, checklist_id, only_missing; 202 / job ID, при активном batch 409 / batch_already_running |
| Прогресс | GET `/evaluations/batch/{job_id}` | job сейчас хранится в памяти процесса |
| Апелляция | POST `/appeals` | `{evaluation_id, criterion_id, comment}` |
| Список обращений | GET `/appeals` | query: evaluation_id, status |
| Решение | POST `/appeals/{id}/review` | decision confirm/change, reviewer_comment, новые значения; ответ EvaluationRead |

Критерий во внутреннем результате: `criterion_id`, `status: scored/na`, `score`, `weight`, `points`, `explanation`, `na_reason`, `evidence[]`, `checked_range`, `source`. Доказательство: `message_index`, `quote`, `timestamp`, `speaker`, `verified`. Не путать внутренний результат с официальным форматом сдачи.
